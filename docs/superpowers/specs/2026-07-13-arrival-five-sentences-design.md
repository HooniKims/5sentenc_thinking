# 여기에 어떻게 오셨어요?

중학생이 등교하거나 행사장에 온 경험을 한 문장에서 다섯 문장으로 넓혀 보는 짧은 아이스브레이커다. 학생은 먼저 스스로 쓰고, 막힐 때만 AI에게 질문을 받는다. AI는 문장을 대신 완성하지 않는다. 놓쳤던 장면을 떠올리게 하고, 표현을 넓히는 데만 쓴다.

## 수업의 흐름

교사는 수업용 세션을 열고 QR을 보여 준다. 학생은 휴대폰이나 태블릿으로 접속해 랜덤 닉네임을 확인하거나 바꾼 뒤, “여기에 어떻게 오셨어요?”에 답하는 첫 문장을 쓴다.

학생은 다섯 문장을 한 번에 쓰지 않는다. 한 문장을 쓰면 다음 칸이 열리고, 다섯 번째 문장까지 같은 흐름을 반복한다. 처음 쓴 문장과 완성한 다섯 문장은 마지막에 나란히 보여 준다. 학생이 자기 표현과 관찰이 어떻게 달라졌는지 직접 확인하는 마무리다.

각 단계에는 `도움!` 버튼이 있다. 이 버튼을 누르면 Solar Pro 3가 현재 단계와 이미 쓴 문장을 보고, 다음 생각을 여는 질문 하나를 보낸다. 예를 들어 길, 사람, 소리, 냄새, 날씨, 감정처럼 주변을 다시 보게 하는 질문이다. 답을 써 주거나 문장을 고쳐 주지 않는다.

## 학생 화면

학생 화면은 콘페스타의 보라색 무대, 라임 포인트, Paperlogy 글꼴, AI MC 캐릭터를 쓴다. 말풍선은 화면 상단에 따로 두고, 오른쪽 아래의 캐릭터는 학생을 가리지 않은 채 함께 생각하는 분위기만 더한다.

학생이 쓰는 문장은 흰색으로 표시한다. 글자가 배경에 묻지 않도록 0.65px 안팎의 얇은 검은 외곽선과 약한 그림자를 적용한다. 입력값은 자동 저장하고, 연결이 잠시 끊겨도 기기에 남겨 두었다가 연결이 돌아오면 다시 보낸다.

도움 요청이 진행되는 동안에는 같은 학생이 버튼을 반복해서 누를 수 없다. “생각을 여는 질문을 준비하고 있어요”라는 안내를 보여 준다. 응답이 늦거나 실패하면 단계별로 준비한 안전 질문을 바로 보여 준다.

## 교사 대시보드

교사는 한 화면에서 학생의 닉네임, 1~5단계 진행 상태, 마지막 문장, 입력 중인 상태, 도움 요청 상태를 실시간으로 본다. 실제 이름은 쓰지 않는다.

도움 요청이 들어오면 해당 학생 카드는 즉시 목록 맨 위로 올라간다. 우선순위는 `도움 요청 중`, `질문 생성 중`, `질문 전달 뒤 다음 문장을 기다리는 학생`, `작성 중`, `완성` 순서다. 학생이 다음 문장을 쓰면 일반 작성 카드로 내려간다. 요청이 여러 개여도 각 카드가 이 순서를 따르므로 교사는 도움이 필요한 학생부터 볼 수 있다.

도움 요청 카드에는 AI가 만든 짧은 응원 초안도 함께 보인다. 교사는 내용을 확인하고 `캐릭터 응원 보내기`를 누른다. 응원은 학생 화면의 캐릭터 말풍선으로 도착한다. 자동 발송하지 않는다. 교사는 직접 타이핑하지 않아도 되며, AI가 만든 문장도 한 번 더 살펴볼 수 있다.

참여 인원은 30명으로 제한하지 않는다. 첫 구현은 한 세션에 100명이 동시에 접속하고 문장을 저장하거나 도움을 요청하는 상황을 기준으로 확인한다. 요청이 한꺼번에 들어오면 학생별 요청 ID와 상태를 가진 대기열에서 처리한다. 같은 학생의 중복 요청은 하나로 합친다.

## 기술 구성

학생 앱과 교사 대시보드는 React·TypeScript 웹 앱으로 만든다. 교사 노트북에서 수업 세션을 열고, 학생은 QR로 같은 세션에 접속한다. Firebase Firestore가 세션, 학생별 작성 상태, 도움 요청, 응원을 실시간으로 동기화한다. 각 화면은 Firestore의 변경을 구독하므로 새로 고치지 않아도 대시보드가 바뀐다.

학생은 Firebase 익명 인증으로 접속한다. 각 학생 문서는 자기 계정으로만 만들고 고칠 수 있다. 교사는 Firebase 이메일/비밀번호 인증 뒤 `teachers` 컬렉션에 등록된 계정만 대시보드와 세션 초기화를 쓸 수 있다. Firestore 보안 규칙이 이 구분을 강제한다.

세션 데이터는 `sessions/{sessionId}` 아래에 둔다. 학생 문장은 `participants/{participantId}`, 도움 요청과 AI 질문은 `helpRequests/{requestId}`, 교사 응원은 `cheers/{cheerId}`에 분리한다. Firestore의 실시간 구독은 도움 요청 상태와 학생 카드의 우선순위를 즉시 갱신한다.

AI 호출은 서버에서만 한다. 브라우저에는 API 키를 보내지 않는다. Upstage Solar Pro 3의 모델 식별자는 `solar-pro3-260323`으로 둔다. 구현할 때 다음 환경변수를 `.env`에 넣는다.

```env
UPSTAGE_API_KEY=
UPSTAGE_MODEL=solar-pro3-260323
VITE_FIREBASE_API_KEY=
VITE_FIREBASE_AUTH_DOMAIN=
VITE_FIREBASE_PROJECT_ID=
VITE_FIREBASE_STORAGE_BUCKET=
VITE_FIREBASE_MESSAGING_SENDER_ID=
VITE_FIREBASE_APP_ID=
FIREBASE_ADMIN_PROJECT_ID=
FIREBASE_ADMIN_CLIENT_EMAIL=
FIREBASE_ADMIN_PRIVATE_KEY=
```

학생의 실제 이름, 연락처, 사진, 평가 정보는 입력하거나 저장하지 않는다. AI에는 익명 식별값, 현재 단계, 필요한 문장만 전달한다. 전화번호처럼 개인정보로 보이는 입력은 AI 요청 전에 막는다. 교사가 수업을 끝내고 세션을 초기화하면 문장, 도움 요청, 응원 기록을 함께 지운다.

## 확인할 것

- 학생 100명이 동시에 문장을 저장하고 도움을 요청해도 카드 상태와 우선순위가 맞게 바뀐다.
- 도움 요청 학생은 즉시 대시보드 상단으로 올라가고, 다음 문장을 쓰면 일반 작성 목록으로 돌아간다.
- AI는 도움 요청에 질문 하나만 보내며, 학생의 문장을 대신 쓰지 않는다.
- AI 응답이 지연되거나 실패해도 준비한 질문으로 활동이 이어진다.
- 교사 응원은 검토와 버튼 클릭 뒤에만 학생에게 전달된다.
- 새로 고침과 네트워크 재연결 뒤에도 학생의 작성 중인 문장과 대시보드 상태가 맞는다.
- Firebase 익명 인증 학생은 자기 문서만, 등록된 교사는 해당 세션의 모든 문서만 읽고 쓴다.
- 세션 초기화 뒤에는 이전 학생 기록을 다시 볼 수 없다.
