# 고정 작성대와 문장 보관함 설계

## 목적

학생이 한 문장을 저장할 때마다 작성 칸이 아래로 밀리거나 화면이 위로 움직이지 않게 한다. 앞에서 쓴 생각은 잃지 않되, 다음 문장을 쓰는 자리는 다섯 단계 내내 같은 위치에 둔다.

이 설계는 중학생이 휴대폰이나 태블릿으로 참여하는 수업을 기준으로 한다. 디디와 `도움!`은 학생의 생각을 대신하지 않고, 현재 문장을 이어 갈 질문을 건네는 역할을 유지한다.

이 문서는 [순차 작성과 대시보드 삭제 설계](2026-07-13-sequential-writing-and-dashboard-deletion-design.md)의 학생 작성 화면 레이아웃을 구체화한다. 해당 문서의 문장 저장, 개인정보 보호, AI 입력 경계, 대시보드·삭제 규칙은 그대로 따른다. 두 문서의 화면 배치가 다르면 이 문서가 우선한다.

## 확정한 경험

### 평소 화면

- 작성 화면은 활동 중 세로 스크롤 목록이 아니다. 화면의 높이는 고정하고, 문장 수가 늘어도 작성대의 위쪽 시작점과 하단 버튼 위치를 바꾸지 않는다.
- 상단에는 현재 단계와 메인 질문 `여기에 어떻게 오셨어요?`가 보인다. 디디와 안내 말풍선은 기존 연출을 유지하되, 작성 영역의 높이나 위치를 밀어내지 않는 레이어로 둔다.
- 작성대 위에는 터치 가능한 `문장 보관함` 한 줄을 둔다. 예: `지금까지 쓴 문장 2개`.
- 보관함이 닫혀 있을 때는 가장 최근에 저장한 문장만 최대 두 줄로 미리 보여 준다. 긴 문장은 말줄임 처리한다. 이전 문장이 아직 없으면 보관함과 미리보기는 보이지 않는다.
- 작성대에는 현재 단계의 한 문장 입력칸, 개인정보 안내, `도움!`, `문장 저장`이 있다. 입력칸은 처음부터 네 줄 높이로 보인다. 더 긴 입력은 입력칸 안에서만 스크롤되며, 활동 화면 전체나 버튼 위치는 움직이지 않는다.

### 문장 저장

1. 학생이 한 문장을 저장하면 확정 문장 배열에만 추가한다. 초안은 비우고, 다음 단계의 입력칸을 같은 자리에 둔다.
2. 보관함의 개수와 최근 문장 미리보기만 바꾼다. 과거 문장 카드들을 본문 흐름에 추가하지 않는다.
3. 입력칸으로 포커스를 돌릴 때는 `preventScroll`을 사용한다. 저장·도움 응답·단계 변경을 이유로 활동 카드에 `scrollTo`를 호출하지 않는다.
4. 다섯 번째 문장은 기존처럼 완료 화면에서 하나의 문단으로 보여 준다. 이 완료 화면은 읽기 전용 결과 화면이므로, 내용이 작은 기기 높이를 넘을 때만 자체 스크롤을 허용할 수 있다.

### 문장 보관함과 수정

1. 보관함의 텍스트, 미리보기, 여백을 포함한 전체 영역은 하나의 버튼이다. 클릭·터치·키보드 Enter/Space로 열린다.
2. 열리면 현재 작성 화면 위에 문장 보관함 대화상자가 뜬다. 저장한 문장을 번호와 함께 모두 읽을 수 있고 각 문장에 `수정` 버튼이 있다. 다섯 문장 이하여서 목록 자체가 길어지는 문제는 없다.
3. `수정`을 누르면 보관함을 닫고 작은 문장 수정 대화상자를 연다. 중첩된 모달을 만들지 않는다.
4. 수정 대화상자에는 선택한 한 문장만 있고, `저장`과 `취소`가 있다. 저장 시 기존 문장만 교체한다. 현재 작성 중인 초안, 현재 단계, 도움 상태는 유지한다.
5. 저장·취소·닫기를 마치면 수정 대화상자는 닫히고, 학생은 원래의 고정 작성대로 돌아온다. 수정 때문에 문장 보관함을 다시 열거나 화면을 스크롤하지 않는다. 포커스는 보관함을 열기 전의 현재 입력칸으로 복원한다.

## 선택하지 않은 방식

- 모든 확정 문장을 작성대 위에 카드로 계속 쌓지 않는다. 네다섯 문장이 되면 작성대를 밀고 활동 카드 스크롤을 만들기 때문이다.
- 이전 문장을 한 줄씩 항상 노출하지 않는다. 생각의 연결은 좋지만 문장 수에 따라 작성 위치가 달라진다.
- 문장 수만 보이고 내용이 전혀 보이지 않는 방식도 쓰지 않는다. 바로 전 생각을 떠올리는 데 필요한 맥락이 부족하다.
- 앞 문장 수정을 별도 페이지로 보내지 않는다. 학생이 사고 흐름을 잃고 현재 초안이 사라질 위험이 있다.

## 화면 구조와 상태 경계

### 학생 화면 구성

`App`의 활동 화면은 다음의 독립된 부분으로 나눈다.

| 부분 | 책임 | 위치와 스크롤 |
| --- | --- | --- |
| 활동 헤더 | 단계, 메인 질문, 개인정보가 아닌 안내 | 상단 고정 영역 |
| 디디 안내 레이어 | 시작 연출, 도움 질문, 제스처 | 작성대의 배치를 바꾸지 않는 절대 위치 레이어 |
| 문장 보관함 트리거 | 문장 수와 최근 문장 두 줄 미리보기 | 작성대 바로 위, 높이 고정 |
| 고정 작성대 | 현재 한 문장 입력, 개인정보 안내, 도움·저장 버튼 | 활동 카드 하단의 같은 자리 |
| 문장 보관함 대화상자 | 확정 문장 전체 확인과 수정 시작 | 화면 위 오버레이, 내부만 필요할 때 스크롤 |
| 문장 수정 대화상자 | 문장 하나 수정·저장·취소 | 화면 위의 작은 오버레이 |

활동 카드에는 문장 수에 따라 커지는 `.sentence-list`를 두지 않는다. 고정 작성대는 카드 본문 흐름에 따라 아래로 밀리지 않도록 배치한다. 좁은 화면에서는 디디의 크기·안내 말풍선 여백을 줄여 작성대가 우선 보이게 한다. 브라우저 키보드가 열린 상태에서도 활동 카드가 임의로 위로 점프하지 않도록, 실제 보이는 뷰포트 높이를 기준으로 여백을 조정한다.

### 상태와 저장

- `sentences`: 확정 문장 배열. 기존과 같이 Firestore에 저장할 수 있는 유일한 학생 글이다.
- `draft`: 현재 작성 중인 한 문장. 브라우저 메모리에만 두고 저장·AI 요청에 보내지 않는다.
- `historyOpen`: 문장 보관함 대화상자의 열림 상태. UI 상태일 뿐 기록하지 않는다.
- `editingSentence`: 수정 중인 문장의 인덱스와 임시 값. 저장할 때만 `sentences`의 해당 항목을 교체한다.

문장 보관함, 수정 대화상자, 최근 문장 미리보기는 모두 `sentences`에서 파생한다. 새로운 Firestore 컬렉션, 필드, 보안 규칙, 대시보드 데이터는 추가하지 않는다. 진행자 화면은 기존처럼 확정 문장만 실시간으로 본다.

## 안전한 도움 흐름

- `도움!`을 눌러도 고정 작성대나 보관함의 높이를 바꾸지 않는다. 분석 중 안내와 디디 말풍선은 기존 안내 레이어 안에서 바뀐다.
- 현재 초안과 확정 문장은 여전히 AI 제공자에게 보내지 않는다. 비식별 작성 신호와 사전 검토 질문만 사용한다.
- 도움을 받은 뒤에도 입력칸은 같은 위치에 있고, 학생이 자신의 말로 이어 쓴다. 답안·예시·고쳐 쓴 문장을 보여 주지 않는다.
- 개인정보 안내와 확정 전 차단은 유지한다.

## 예외와 접근성

- 저장 문장이 없을 때는 보관함 트리거를 표시하지 않는다.
- 최근 문장 미리보기는 시각적으로 두 줄에서 자르지만, 보관함 안에서는 원문 전체를 읽을 수 있다.
- 보관함과 수정 대화상자는 ESC, 닫기 버튼, 바깥 영역 클릭으로 닫을 수 있다. 키보드 포커스는 열린 대화상자 안에 머물고, 닫을 때 현재 작성 입력칸으로 돌아간다.
- 수정한 문장이 개인정보 또는 한 문장 규칙을 통과하지 않으면 저장하지 않고, 수정 대화상자 안에서 이유를 알린다. 원래 문장은 그대로 남긴다.
- 저장 중 오류가 나면 작성대의 초안과 보관함 상태를 잃지 않는다. 기존의 안전한 저장 실패 안내를 사용한다.
- `prefers-reduced-motion`에서는 보관함·수정 대화상자 전환과 디디 동작을 즉시 전환한다.

## 검증 기준

자동 테스트와 실제 브라우저에서 다음을 확인한다.

1. 첫 문장을 저장해도 두 번째 입력칸의 화면상 위치와 활동 카드 스크롤 위치가 바뀌지 않는다. 다섯 번째 문장까지 반복한다.
2. 보관함을 닫은 상태에서 문장 수와 마지막 문장 최대 두 줄만 보인다. 긴 문장을 저장해도 작성대의 높이·버튼 위치는 유지된다.
3. 보관함의 어느 부분을 눌러도 전체 목록이 열리고, 키보드로도 열고 닫을 수 있다.
4. 앞 문장을 수정한 뒤에도 현재 초안과 단계가 보존되며, 저장·취소 뒤 포커스는 현재 입력칸으로 돌아온다.
5. `도움!` 분석 시작·완료가 활동 카드의 스크롤 위치를 바꾸지 않는다.
6. 개인정보 안내·차단, 초안 비저장, 원문 없는 도움 요청, 실시간 대시보드의 확정 문장 표시가 회귀하지 않는다.
7. 320px 폭 휴대폰, 태블릿 폭, 데스크톱 폭과 모바일 가상 키보드 환경에서 작성대와 주요 버튼이 가려지지 않는지 수동으로 확인한다.

## 범위 밖

- 문장 보관함에서 문장 순서를 바꾸거나 삭제하는 기능
- 다섯 문장을 넘는 추가 단계
- AI가 학생 문장을 직접 고치거나 다음 문장을 작성하는 기능
- 진행자 대시보드·Firestore 권한·응원 기능의 동작 변경
