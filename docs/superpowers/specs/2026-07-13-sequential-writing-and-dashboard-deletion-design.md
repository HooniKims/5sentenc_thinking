# 이어 쓰는 다섯 문장과 수업 기록 정리

> 수업의 QR·상태 전환·보관 기준은 [수업 연결과 보관 흐름](../../session-archive-lifecycle.md)을 함께 따른다. 이 문서의 이전 표현과 다르면 해당 문서의 `active → archiving → archived` 흐름이 우선한다.

## 목표

학생은 한 생각을 처음부터 다시 쓰지 않는다. 먼저 쓴 문장을 카드에 남기고, 다음 빈 칸에 한 문장씩 이어 쓴다. 다섯 문장이 모이면 하나의 문단으로 읽고, 필요하면 앞 문장도 고친다.

디디는 답을 대신 만들지 않는다. 학생이 `도움!`을 누르면 기기 안에서 작성 흐름을 살피고, 검토된 질문 하나로 다음 생각을 연다. 원문을 AI에 보내지 않으면서도 학생이 놓친 장면·감각·행동·관점을 돌아보게 하는 것이 목표다.

## 학생 기록과 개인정보

- 입력칸 바로 아래에 `이름·연락처·학교·학급·주소는 쓰지 않아요.`를 안내한다.
- 전화번호, 이메일, 자택 주소, 학교·학급, 자기 이름처럼 개인정보로 보이는 문장은 저장을 막고 다시 쓰도록 안내한다.
- 작성 중인 초안은 Firestore에 저장하지 않는다. 개인정보 검사를 통과한 확정 문장만 진행자 대시보드에 실시간으로 보인다.
- Firestore 규칙도 알려진 개인정보 형식(전화번호·이메일·학교·학급·광역 주소 표기)과 문서 형식을 다시 검사한다. 의미만으로 식별되는 정보까지 완벽히 판별할 수는 없으므로, 입력 전 안내와 화면 차단을 함께 사용한다.

이 감지는 학생이 입력 전 안내를 따르도록 돕는 안전장치다. 감지 결과를 AI에 전달하거나, 식별 정보를 추정하려 하지 않는다.

## 디디의 실시간 도움

`도움!`을 누르면 버튼은 잠시 비활성화되고 말풍선에는 `디디가 문장 사이를 살펴보고 있어요.`가 보인다. 기기 안에서 다음의 비식별 신호만 만든다.

- 현재 단계와 확정 문장 수
- 초안 길이 구간
- 장면·감각·행동·관점 변화가 드러났는지
- 앞 문장과 겹치는 말이 있는지

익명 Firebase ID 토큰을 확인한 서버가 이 신호만 Solar Pro 3에 보낸다. 모델은 `0`, `1`, `2` 중 하나만 돌려주고, 서버는 그 번호를 사전 검토한 단계별 질문으로 바꾼다. 따라서 모델은 학생 원문을 받지 않고 자유 문장도 생성하지 않는다. 질문은 답·예시·고쳐 쓰기·평가·신원 요청을 포함하지 않는다.

익명 학생 토큰만 도움 요청에 쓸 수 있다. 같은 학생의 반복 요청은 함수 인스턴스에서 1분에 최대 8번으로 제한한다. 인증 실패, 지연, 숫자 형식 위반, 서비스 오류 때만 로컬 안전 질문으로 바꾼다. 다중 인스턴스 전체의 남용 방어는 배포 환경의 WAF 또는 공유 제한 저장소를 추가할 때 강화한다.

## 진행자 대시보드와 삭제

진행자는 이메일 로그인 뒤 확정 문장, 작성 단계, 도움 요청, 완료 상태를 실시간으로 본다. 도움 요청 카드는 먼저 보인다.

진행자는 QR을 안내하기 전에 대시보드에 로그인해 세션을 연다. 그래야 학생의 첫 확정 문장부터 안전하게 기록된다.

### 학생 한 명의 기록 삭제

확인 뒤 해당 `participants`, 같은 `ownerUid`의 `helpRequests`, `cheers`를 400개 이하 batch로 지운다. 삭제 표시를 먼저 남겨 늦게 도착한 학생 저장이 같은 수업에서 기록을 다시 만들지 못하게 한다.

### 수업 전체 기록 삭제

확인 뒤 세션을 먼저 `archiving`으로 바꿔 기존 QR과 학생 참여를 즉시 멈춘다. 이후 `participants`, `helpRequests`, `cheers`, 개별 삭제 표시를 400개 이하 batch로 지운다. 모든 삭제가 끝난 경우에만 세션은 `archived`가 되고, 수업을 연 시각과 보관 시각만 보관함에 남긴다. 중간에 실패하면 `archiving`에 머물며 진행자는 같은 정리를 다시 시도할 수 있다.

## Firestore 권한

- 진행자 권한은 `teachers/{uid}.active == true`로만 판단하며, 클라이언트는 이 문서를 만들거나 바꿀 수 없다.
- 학생은 열린 세션에서 자신의 `ownerUid`를 유지한 participant 문서만 만들거나 고칠 수 있다.
- 학생은 진행자 기록, 다른 학생 기록, 삭제 표시를 읽거나 바꿀 수 없다.
- 진행자만 삭제와 세션 상태 전환을 할 수 있다.

## 검증 범위

- 문장 카드, 수정, 다섯 문장 문단
- 개인정보 안내·차단과 초안 비저장
- 원문 없는 도움 요청, ID 토큰 확인, 요청 제한, 안전 질문 번호 변환
- 개별 삭제 표시와 전체 삭제의 `archiving → archived` 전환·재시도
- Firestore 실환경 권한 검사, 데스크톱·태블릿·휴대폰 화면 검토
