# 한 문장 확장하기 — 기획안

## 원래 기획 의도

한 문장에서 출발해 그것을 **점점 확장**한다. "여기까지 어떻게 왔는지"를 한 문장으로 쓰고,
그 한 문장을 두 문장으로, 다시 더 늘려 간다. 확장하다 보면 처음엔 놓쳤던 주변 풍경과 사람,
그날의 기분, 날씨가 떠오르며 **생각 자체가 넓어진다**.

## 지금 앱과의 차이

| | 지금 ("5문장 길찾기") | 이 기획 ("한 문장 확장") |
|---|---|---|
| 쓰는 방식 | 서로 다른 5개 장면을 차례로 나열 | 같은 한 순간을 계속 다시 보며 깊게 |
| 학생 활동 | "그다음엔?" (진행) | "무엇을 놓쳤지?" (재발견) |
| 결과물 | 5개 장면의 이어 읽기 | 한 기억이 자라난 한 편의 글 |
| 디디 질문 | 다음 장면을 묻기 | 안 본 것을 묻기(감각·사람·기분·날씨·이유) |

## 왜 이 방향이 더 좋다고 보는가 (솔직한 의견)

1. **AGENTS.md 철학에 더 맞다.** 우리 앱의 핵심은 "생각을 넓히는" 것인데, 확장은 곧 넓힘 그 자체다.
   나열형 5문장은 자칫 "그리고… 그리고…" 기계적 목록이 되기 쉽다.
2. **생각의 성장이 눈에 보인다.** "나는 '버스 타고 왔어요' 한 줄만 썼는데, 다시 보니 노을도,
   찬 바람도, 설레던 마음도 있었네" — 이 메타인지 순간이 학습의 핵심이다.
   AGENTS.md가 말하는 "사고 과정과 변화가 보이는 경험"이 자연스럽게 나온다.
3. **디디의 질문이 진짜 생성적이 된다.** "다음은?"보다 "무엇을 놓쳤나?"가 더 어렵고 더 풍부하다.
   지금 help API가 이미 계산하는 `detailKinds`(장면·감각·행동·변화)가 "아직 확장 안 한 차원"으로 바로 매핑된다.

## 확장 메커니즘 — 확정 필요한 핵심 결정

같은 순간을 확장한다는 게 구체적으로 어느 쪽인가:

- **(A) 덧붙여 키우기 (추천)**: 씨앗 문장은 그대로 두고, 다시 보며 새로 알아챈 것을 한 문장씩
  더해 글을 키운다. 문장 수가 늘며 한 편의 글이 된다.
  - 예) "버스를 타고 학교에 왔어요."
    → "버스를 타고 학교에 왔어요. **창밖으로 아침 해가 반짝였어요.**"
    → "…반짝였어요. **옆자리 친구는 아직 졸고 있었어요.**"
    → "…졸고 있었어요. **나는 조금 설레는 마음이었어요.**"
- (B) 같은 문장을 더 길고 풍부하게 다시 쓰기: 문장 수는 적게 두되 한 문장을 계속 고쳐 두껍게.

원래 표현("한 문장을 두 문장으로 확장")과 "놓쳤던 풍경·사람·기분·날씨"를 보면 **(A)** 로 읽힌다.

> **확정: (A) 덧붙여 키우기.** 씨앗 문장은 보존하고, 다시 보며 알아챈 것을 한 문장씩 더해 한 편의 글로 키운다.

## 화면·흐름 (A 기준)

1. **씨앗**: "오늘 여기까지 어떻게 왔는지 한 문장으로 적어 보세요."
2. **확장 라운드**: 매 라운드 디디가 아직 안 본 차원 하나를 짚어 준다.
   "그때 창밖은 어땠어요?"(감각) / "곁에 누가 있었나요?"(사람) / "그날 마음은요?"(기분)
   / "날씨는 어땠죠?"(날씨). 학생은 그 순간을 다시 보고 한 문장을 더한다.
3. **성장 보이기**: 자라나는 글을 한 덩어리로 보여 주고, "처음 생각 → 지금 생각"을 나란히 둔다.
4. **마무리**: 밋밋한 한 줄이 생생한 기억으로 자란 걸 되읽는다. 지금의 "디디의 마법 이어 읽기"가
   오히려 더 잘 맞는다(조각 5개가 아니라 한 기억이므로).

## 기존 코드 재사용 (대부분 그대로)

- Firebase 인증·Firestore·교사 대시보드·디디 3D·help API·안전 규칙(개인정보 차단) 전부 재사용.
- 데이터 모델: `sentences[]`는 유지하되 **의미가 "5개 독립 장면" → "자라나는 한 글"** 로 바뀐다.
  씨앗은 `sentences[0]`로 보존. 성장 과정을 교사가 보고 싶으면 버전 스냅샷을 얇게 남기는 것도 고려.
- 바뀌는 부분: 프롬프트/질문 문구(studentWriting·helpGuidance), 화면 구성(카드 5장 → 자라는 글),
  진행 표시(5단계 → "n번째로 알아챈 것"), 완료 문구.

## 설계 시 주의

- **인지 부하**: 확장은 나열보다 어렵다. 디디가 **한 번에 한 차원**만 부드럽게 권한다.
- **덧붙이기 vs 통째 고치기**: 기본은 "덧붙이되 문맥 보여 주기". 앞 문장 수정은 지금처럼 허용.
- **끝점**: 딱 5개가 아니라 "네다섯 가지쯤 알아채면"으로 부드럽게. 학생이 원하면 멈출 수 있게.
- **숫자 프레이밍**: 문장 수는 잔잔한 진행 표시로만. "칸 채우기"가 아니라 "알아채기"로 말한다.

## 중1 사용성 원칙 (최우선 제약)

대상은 중학교 1학년(만 12~13세). 확장은 나열보다 본질적으로 조금 더 어렵다.
성패는 **디디 질문이 얼마나 구체적이냐**에 달려 있다. 아래를 철칙으로 삼는다.

1. **추상 금지, 구체·감각으로 한 가지만 묻는다.**
   - ✗ "무엇을 놓쳤나요?" / "생각을 더 넓혀 볼까요?" (막힌다)
   - ✓ "창밖으로 뭐가 보였어요?" / "무슨 소리가 들렸어요?" / "곁에 누가 있었어요?" (바로 쓴다)
2. **쉬운 차원부터 → 어려운 차원 순.** 본 것(가장 쉬움) → 소리·냄새 → 사람 → 날씨 → 기분(가장 추상).
   기분은 충분히 몸이 풀린 마지막에.
3. **문장 시작만 예시로 보여 준다(채워 주진 않음).** "예: 창밖으로 ___이 보였어요."
   빈칸 느낌으로 문턱을 낮추되, AI가 대신 쓰지 않는 철학은 지킨다.
4. **한 번에 한 문장만 더한다.** 통째로 고쳐 쓰라고 하지 않는다(그래서 A안이 중1에 유리).
5. **막히면 강요하지 않는다.** "잘 안 떠오르면 다른 걸 물어볼게요" → 디디가 더 쉬운/다른 차원으로.
6. **끝이 분명하다.** 무한 확장 아님. "네 가지쯤 알아채면 완성"(씨앗+4=5문장). 진행이 보이고 끝이 있어 부담이 적다.
7. **화면은 지금 할 일에 집중.** 자라난 글은 위에 조용히 쌓이고, 디디 질문·입력칸이 항상 또렷하게 보인다.
8. **모든 말은 한 줄, 쉬운 말.** 읽기·타이핑 부담 최소(모바일 가정).

> 요지: 확장 모델을 쓰되, 중1에겐 **"다시 생각해 봐"가 아니라 "그때 하늘은 무슨 색이었어?"** 로 묻는다.
> 구체적 감각 질문은 오히려 답하기 쉽고 재미있다 — 어려움이 아니라 강점이 된다.

## 구현 계획 (A 확정 기준)

핵심 통찰: **데이터·인증·규칙·디디·help API는 거의 그대로**. 확장 모델은 기존 파이프라인의
**재프레이밍**이지 새로 짓는 게 아니다. `sentences[]`(≤5)와 `currentStep`(1~5)을 그대로 쓰되
의미만 "씨앗 + 알아챔 4번 = 최대 5문장"으로 바꾼다 → **firestore.rules 변경 불필요**.

### Phase 1 — 말·질문 재프레이밍 (개념 변화의 핵심, 코드 위험 낮음)
- `src/lib/studentWriting.ts`: `openingDidiSpeech`·`guideQuestions`·`guideCopies`를
  "씨앗 한 문장 → 다시 보며 알아챔"으로. 1단계=씨앗, 2~5단계=확장 유도.
  **중1 원칙 반영**: 단계별로 구체·감각 질문 고정 순서(본 것→소리·냄새→사람→날씨→기분),
  문장 시작 예시("예: 창밖으로 ___") 제공.
- `src/lib/helpGuidance.ts` + `api/help.ts`: 이미 있는 `detailKinds`(장면·감각·행동·변화)로
  **아직 안 쓴 차원**을 골라 "그때 [차원]은 어땠어요?"로 확장 질문. 백엔드 로직은 유지, 방향만 전환.
  막히면(초안 비어있음 신호) 더 쉬운 차원으로 바꿔 묻는 폴백.

### Phase 2 — 자라는 글 화면
- `src/App.tsx`·`SentenceList`: 카드 5장 나열 → **한 덩어리로 흐르는 글** + 새로 더한 문장 강조.
- "처음 생각 → 지금 생각": 씨앗(`sentences[0]`)을 늘 보이게 두어 성장이 눈에 보이게.
- 진행 표시: "n / 5 단계" → "n번째로 알아챈 것"(잔잔한 진행, 칸 채우기 아님).
- 입력 문구: "다음 문장" → "새로 알아챈 것을 한 문장 더해 볼까요?"

### Phase 3 — 완료(마법) 재프레이밍
- `CompletionExperience`: 지금의 이어 읽기 마법이 오히려 더 잘 맞음.
  문구를 "한 줄이 이렇게 자랐어요"로, 씨앗→자란 글 변화를 보여 주는 리빌로.

### Phase 4 — 교사 대시보드 문구 소소한 조정(선택)

### 진행 원칙
- 발표 버전(main)은 절대 건드리지 않는다. 이 실험은 워크트리 브랜치에서만.
- Phase마다 Vercel 프리뷰 배포로 실제 학생 흐름을 눈으로 확인.
- 테스트는 기존 스위트 유지 + 재프레이밍된 문구/흐름에 맞춰 갱신.
